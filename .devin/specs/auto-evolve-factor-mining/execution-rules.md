# 严格执行规范

> 本规范是铁律，违反任何一条 = 任务未完成

## 1. 核心原则

### 1.1 零容忍规则
- **禁止**使用假数据、mock数据、随机数据填充任何API响应
- **禁止**标记任务完成除非**所有**验收测试通过
- **禁止**提交无法运行的代码
- **禁止**绕过单元测试

### 1.2 数据真实性（红线）
- 所有数据必须来自：真实计算 / TQSDK / 数据库查询
- API返回的数据必须是真实可验证的
- 临时占位数据必须标记 `TODO: 临时实现` 并在24小时内替换

## 2. 任务验收标准模板

每个任务必须包含以下验收项：

```markdown
### Task X: 任务名称

#### 验收标准（必须全部通过）
- [ ] 验收1: 运行 `xxx` 命令，预期输出 `yyy`
- [ ] 验收2: 调用 API `GET /api/xxx`，返回数据必须来自真实计算
- [ ] 验收3: 运行单元测试 `pytest tests/test_xxx.py`，全部通过
- [ ] 验收4: 代码审查：无TODO，无假数据，有完整错误处理

#### 禁止事项
- 禁止使用假数据
- 禁止跳过错误处理
- 禁止硬编码

#### 依赖
- 依赖 Task Y 完成
```

## 3. 每日检查点

每天结束必须回答：
1. 今天完成了哪个任务？
2. 验收测试全部通过了吗？
3. 能演示这个功能吗？
4. 有遗留TODO吗？什么时候解决？

**不能演示 = 当天任务未完成**

## 4. 代码提交标准

### 4.1 提交前检查清单
```bash
# 必须运行并通过
pytest tests/                    # 单元测试
ruff check backend/              # 代码风格
mypy backend/                    # 类型检查
```

### 4.2 提交信息规范
```
feat(Task X): 完成功能描述

- 实现xxx
- 通过验收测试：
  - 验收1: xxx
  - 验收2: xxx
- 单元测试覆盖率: xx%

BREAKING CHANGE: 无
```

## 5. 技术债务追踪

### 5.1 TODO标记规范
```python
# TODO(任务ID): 问题描述，解决期限
# TODO(Task-5): 当前使用简化算法，需在Task 8替换为完整版，期限：2025-05-20
```

### 5.2 债务清单
每个TODO必须在项目根目录的 `TECH_DEBT.md` 中登记：
```markdown
| ID | 位置 | 问题 | 引入时间 | 解决期限 | 状态 |
|---|---|---|---|---|---|
| TD001 | backend/app/main.py:45 | 临时mock数据 | 2025-05-16 | 2025-05-17 | 待解决 |
```

## 6. 测试要求

### 6.1 单元测试覆盖率
- 核心算法：>90%
- API路由：>80%
- 工具函数：>70%

### 6.2 测试类型
- 单元测试：`tests/unit/`
- 集成测试：`tests/integration/`
- 验收测试：`tests/acceptance/`

### 6.3 测试命名
```python
def test_被测对象_场景_预期结果():
    """测试描述"""
    pass

def test_factor_registry_load_primitives_success():
    """测试因子注册表能成功加载所有原语"""
    pass
```

## 7. 代码审查清单

### 7.1 必须检查项
- [ ] 无print调试语句
- [ ] 无硬编码配置
- [ ] 有完整的错误处理
- [ ] 有日志记录
- [ ] 类型注解完整
- [ ] 文档字符串完整

### 7.2 性能检查
- [ ] 无N+1查询
- [ ] 大数据集使用分页
- [ ] 计算密集型使用缓存

## 8. 违规后果

| 违规类型 | 后果 |
|---------|------|
| 提交假数据 | 任务回滚，重新实现 |
| 跳过测试 | 任务标记未完成 |
| 未解决TODO超期 | 阻塞后续任务 |
| 验收测试失败 | 禁止提交 |

## 9. 执行流程

```
开始任务
  ↓
编写实现代码
  ↓
编写单元测试
  ↓
运行测试（必须全部通过）
  ↓
代码自查（检查清单）
  ↓
运行验收测试
  ↓
全部通过？→ 是 → 标记完成
  ↓ 否
修复问题
  ↓
重复测试流程
```

3. 每个交付的代码都经过完整测试
4. 有问题立即提出，不隐瞒
