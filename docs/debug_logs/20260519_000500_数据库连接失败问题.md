## 🐛 问题根因分析

### 问题1：基础设施检查逻辑缺陷

**位置**: `bat启动文件夹/init-data.bat`

**检查逻辑（有缺陷）**:
```batch
docker-compose ps timescaledb 2>&1 | findstr "Up" > nul
if errorlevel 1 (
    echo [INFO] TimescaleDB 未运行，正在启动...
    docker-compose up -d timescaledb redis
) else (
    echo [OK] 基础设施已运行
)
```

**缺陷分析**:
1. `docker-compose ps` 输出的 "Up" 状态匹配可能不准确
2. 即使容器显示 "Up"，数据库内部可能还在初始化中（PostgreSQL需要几十秒启动时间）
3. **缺少数据库连接可用性的真实检查**

### 问题2：缺少数据库启动等待超时处理

启动了数据库容器后，没有足够的等待时间让PostgreSQL完成初始化。

### 问题3：没有更友好的错误提示

当前错误直接抛出SQLAlchemy的原始异常，用户难以理解。

## 🔧 修复方案

### 修复1：改进数据库健康检查逻辑

**修复位置**: `bat启动文件夹/init-data.bat`

**改进前**:
```batch
REM 等待数据库就绪
echo [INFO] 等待数据库就绪...
set "DB_READY=0"
for /L %%i in (1,1,30) do (
    timeout /t 1 /nobreak > nul
    docker-compose exec -T timescaledb pg_isready -U qmt -d quant_db > nul 2>&1
    if !errorlevel! equ 0 (
        set "DB_READY=1"
        goto :db_ready
    )
    echo|set /p=.
)
echo.

:db_ready
```

**改进后**:
```batch
REM 等待数据库就绪
echo [INFO] 等待数据库就绪...
set "DB_READY=0"
set "MAX_RETRIES=60"  # 增加到60秒等待时间
for /L %%i in (1,1,%MAX_RETRIES%) do (
    timeout /t 1 /nobreak > nul
    docker-compose exec -T timescaledb pg_isready -U qmt -d quant_db > nul 2>&1
    if !errorlevel! equ 0 (
        set "DB_READY=1"
        goto :db_ready
    )
    echo|set /p=.
)
echo.

:db_ready
if !DB_READY! equ 0 (
    echo [ERR] 数据库连接超时!
    echo [INFO] 请检查以下内容:
    echo   1. Docker是否正在运行
    echo   2. timescaledb容器是否启动成功: docker-compose ps timescaledb
    echo   3. 查看容器日志: docker-compose logs timescaledb
    echo   4. 手动重启容器: docker-compose restart timescaledb
    echo.
    pause
    exit /b 1
) else (
    echo [OK] 数据库已就绪
)
```

### 修复3：在Python层面添加更友好的错误处理

**位置**: `backend/quant_engine/data/hub.py` - `_connect` 方法

```python
def _connect_with_retry(self) -> None:
    """带重试的数据库连接"""
    max_retries = 5
    retry_delay = 2
    
    for attempt in range(max_retries):
        try:
            self.engine = create_engine(
                self.db_url,
                pool_size=10,
                max_overflow=20,
                pool_pre_ping=True,
                pool_recycle=3600,
                echo=False,
            )
            self._session_factory = sessionmaker(bind=self.engine)
            
            # 测试连接
            with self.engine.connect() as conn:
                conn.execute(text("SELECT 1"))
            
            logger.info("数据库连接成功")
            
            try:
                self._ensure_hypertables()
            except Exception as e:
                logger.warning(f"创建超表时遇到警告（可能已存在）: {e}")
            
            return
            
        except OperationalError as e:
            if attempt < max_retries - 1:
                logger.warning(f"数据库连接失败（尝试 {attempt + 1}/{max_retries}），{retry_delay}秒后重试...")
                logger.debug(f"错误详情: {e}")
                time.sleep(retry_delay)
                retry_delay *= 2  # 指数退避
            else:
                logger.error("=" * 60)
                logger.error("数据库连接失败，请检查：")
                logger.error("  1. Docker是否正在运行")
                logger.error("  2. timescaledb容器是否已启动: docker-compose ps timescaledb")
                logger.error("  3. 数据库端口5432是否可访问")
                logger.error("  4. 环境变量中数据库配置是否正确")
                logger.error("=" * 60)
                raise RuntimeError("数据库连接失败，请检查上述配置") from e
```
