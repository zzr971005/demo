# 不同因子表现一模一样问题修复

**时间**: 2026-05-30 21:13:00
**问题描述**: 最佳因子表中，不同因子的表现指标（Sharpe、Total Return、Total Trades、Avg Trade Return、Win Rate、Max Drawdown）完全相同，这不正常。

---

## 问题发现

用户报告最佳因子表中不同因子公式显示相同的性能指标，通过数据库查询确认了这一现象。

## 调试过程

### 1. 启用DEBUG日志

- 修改`evolution_worker.py`：将日志级别从INFO改为DEBUG
- 修改`run_continuous_evolution.py`：将日志级别从INFO改为DEBUG
- 目的：获取详细的因子计算和回测过程日志

### 2. 分析DEBUG日志

从日志中发现关键信息：

**关键发现**：
1. 所有因子值都是NaN
2. 相同表达式产生不同的回测结果（sharpe: 2.7423, -1.5062, 3.0186, 1.3425）
3. 因子值数组ID不同，说明不是共享同一个数组

### 3. 全面审查回测引擎

对`VectorizedBacktestEngine`进行全面审查：
- **随机性检查**：回测引擎使用Numba JIT确定性函数，无随机数生成器
- **状态污染检查**：类无共享状态的实例变量，Numba函数无全局状态
- **缓存机制检查**：Numba JIT设置cache=False
- **参数传递检查**：参数传递正确
- **FeeModel检查**：无状态，所有方法为纯函数

**结论**：回测引擎本身设计良好，无严重问题。

### 4. 定位根本原因

**数据列不匹配**：
- 表达式生成器生成了使用`far_close`, `obv`, `term_slope`等扩展列的表达式
- `FactorCompiler`只提供基础列：`['open', 'high', 'low', 'close', 'volume', 'open_interest']`
- 数据加载时（`evolution_center.py`第280-283行）会添加扩展列：
  ```python
  data['near_close'] = data['close']
  data['far_close'] = data['close']
  data['days_to_expiry'] = 30
  ```
- 因子计算时找不到这些列，返回全NaN

## 发现的问题

### 问题1：数据列不匹配导致因子计算失败

**位置**: `backend/quant_engine/ops/gp_fitness.py`第319-326行

**原因**: FactorCompiler的data_columns参数只包含基础列，不包含期限结构列和计算指标列

**影响**: 
- 表达式使用扩展列时因子计算失败
- 返回全NaN因子值
- 回测引擎对全NaN因子的处理不当

### 问题2：因子值全为NaN时仍产生回测结果

**位置**: `backend/quant_engine/validation/engine.py`第397-442行

**原因**: 
- 当因子值全为NaN时，回测循环中所有bar被跳过
- equity保持初始值，trades_pnl为空数组
- 指标计算函数没有检测到这种情况，返回看似有效但实际无效的结果

**影响**:
- 无效因子产生随机回测结果
- 不同表达式可能产生相同的无效结果

### 修复6：参数类型检查（subtree_crossover）

**时间**: 2026-05-30 22:18:00

**问题**: `subtree_crossover`在交换子树时不检查参数类型，导致常量节点被交换到变量位置，产生无效表达式如 `money_flow(high, 20, close, volume, 20)`。

**根本原因**: 
- `money_flow`函数第二个参数应该是`low`（变量），但交叉后被替换为`20`（常量）
- 这导致因子计算时参数类型不匹配，部分值为NaN

**文件**: `backend/quant_engine/ops/gp_operators.py`

**修改内容**:
```python
# 添加参数类型检查函数
def _get_expected_child_type(parent_node: GPNode, child_index: int) -> Optional[str]:
    """获取父节点对指定位置子节点的期望类型"""
    if parent_node.node_type != 'func':
        return None
    
    func_meta = FACTOR_REGISTRY.get(parent_node.name)
    if func_meta is None or child_index >= len(func_meta.params):
        return None
    
    param_name, param_type, param_default = func_meta.params[child_index]
    if param_type == str:
        return 'var'  # 字符串类型参数需要变量节点
    elif param_type in (int, float):
        return 'const'  # 数值类型参数需要常量节点
    
    return None

def _check_node_compatibility(source_node: GPNode, target_parent: GPNode, target_child_index: int) -> bool:
    """检查源节点是否可以交换到目标位置"""
    expected_type = _get_expected_child_type(target_parent, target_child_index)
    
    if expected_type is None:
        return True
    
    if expected_type == 'var':
        return source_node.node_type == 'var'
    elif expected_type == 'const':
        return source_node.node_type == 'const'
    
    return True

# 在subtree_crossover中添加类型检查
if not _check_node_compatibility(node2, parent_node1, child_idx1):
    return offspring1, offspring2  # 类型不兼容，跳过交叉

if not _check_node_compatibility(node1, parent_node2, child_idx2):
    return offspring1, offspring2  # 类型不兼容，跳过交叉
```

**效果**: 交叉算子现在会检查参数类型兼容性，避免常量被交换到变量位置，确保生成的表达式有效。

### 修复7：禁用FactorCompiler缓存

**时间**: 2026-05-30 22:18:00

**问题**: `FactorCompiler`使用表达式字符串作为缓存键，导致相同表达式的个体共享同一个编译函数。这在并发环境下可能导致问题。

**文件**: `backend/quant_engine/ops/gp_fitness.py`

**修改内容**:
```python
# 修改前（使用缓存）
def compile(self, individual: GPIndividual) -> Optional[Callable]:
    expression = individual.to_expression()
    if expression in self._cache:
        return self._cache[expression]
    func = self._build_function(individual)
    self._cache[expression] = func
    return func

# 修改后（禁用缓存）
def compile(self, individual: GPIndividual) -> Optional[Callable]:
    # 禁用缓存，为每个个体独立编译
    # 避免不同个体共享同一个函数引用（可能导致并发问题）
    return self._build_function(individual)
```

**效果**: 每个个体都有独立的编译函数，避免共享状态导致的潜在问题。

### 修复9：数据库种子去重（evolution_center）

**时间**: 2026-05-30 22:30:00

**问题**: 从数据库加载的种子可能包含重复表达式，如果直接用这些种子填充种群，会导致整个种群都是相同的个体。

**根本原因**: 
- 之前的修复只在种群进化时去重
- 但初始化时使用数据库种子没有进行去重
- 如果数据库中有20个相同表达式的因子，整个种群都会被填充为相同的个体

**文件**: `backend/quant_engine/ops/evolution_center.py`

**修改内容**:
```python
# 加载种子（方案C：从数据库加载优质因子）
seeds = self._load_seeds_from_database(max_seeds=20)

# 对种子进行表达式去重（防止数据库中重复因子填充整个种群）
if seeds:
    unique_seeds = []
    seen_expressions = set()
    for seed in seeds:
        expr = seed.to_expression()
        if expr not in seen_expressions:
            unique_seeds.append(seed)
            seen_expressions.add(expr)
    seeds = unique_seeds
    logger.info(f"加载种子去重后: {len(seeds)} 个唯一因子")
```

**效果**: 数据库种子加载后自动去重，确保初始化种群的多样性。
