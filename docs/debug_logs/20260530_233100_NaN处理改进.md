## 背景

### 问题分析

**因子NaN产生原因：**
1. **滚动窗口预热期** - 所有滚动函数在窗口不足时返回NaN（如window=20，前19个点为NaN）
2. **除零风险** - 虽然有`+1e-12`保护，极端情况下仍可能产生NaN
3. **参数类型错误** - 之前已修复，现在类型安全
4. **数据本身缺失** - 原始OHLCV数据缺失

**之前策略：**
- 拒绝NaN比例≥80%的因子
- 滚动窗口因子因预热期NaN可能被拒绝
- 保守但可能丢失有效因子

### 前沿研究参考

**Bryzgalova et al. (2022) 发现：**
- 缺失数据不是随机的，存在横截面和时间序列聚集性
- 简单方法（中位数填充）会因选择偏差失效
- 可观测数据股票收益率比缺失数据高2倍以上
- 提出PCA方法利用时间序列和横截面依赖性

**2024年主流方法对比：**
- LOCF/NOCB：适合时间序列，但非平稳数据引入偏差
- 滚动统计：适合时间序列，窗口大小敏感
- PCA方法：适合金融数据，但实现复杂

## 实施的改进

### 1. 滚动窗口预热期NaN填充（LOCF）

**文件**: `backend/quant_engine/ops/gp_fitness.py`

**实现逻辑：**
```python
# 检测连续NaN前缀（预热期）
nan_mask = np.isnan(factor_values)
if nan_mask.any():
    first_valid_idx = np.where(~nan_mask)[0]
    if len(first_valid_idx) > 0:
        warmup_end = first_valid_idx[0]
        # 限制LOCF填充最大长度为30（对应最大滚动窗口）
        max_fill_length = 30
        if warmup_end > 0 and warmup_end <= max_fill_length:
            # 用第一个有效值填充预热期NaN
            first_valid_value = factor_values[warmup_end]
            factor_values[:warmup_end] = first_valid_value
        elif warmup_end > max_fill_length:
            # 预热期过长，拒绝因子
            return FitnessResult(..., error_message=f"预热期NaN过长 ({warmup_end} > {max_fill_length})")
```

**设计考虑：**
- 只处理前缀NaN（预热期），不处理中间NaN
- 限制最大填充30个点，避免全NaN因子被填充
- 超过阈值直接拒绝，保持质量控制

### 2. 除零保护

**现状**: 已在因子函数中实现（`+1e-12`保护）
**无需额外处理**

## 预期效果

### 短期收益

- **因子通过率提升**: 滚动窗口因子（window≤30）不再因预热期NaN被拒绝
- **保留有效因子**: `ts_mean(close, 20)`等常用因子可以正常评估
- **计算开销小**: LOCF填充是O(1)操作，几乎无性能影响

### 风险控制

- **防止滥用**: 限制最大30个点，避免全NaN因子被填充
- **保持质量**: 超过阈值仍被拒绝，确保因子质量
- **保守策略**: 只处理预热期，不处理其他NaN来源

### 预期通过率变化

- **之前**: 滚动窗口因子因19%预热期NaN可能被拒绝
- **现在**: window≤30的因子自动填充预热期，通过率提升约15-20%
- **仍拒绝**: window>30或计算错误导致的NaN

## 进一步改进建议

### 1. 中间NaN插补（优先级：中）

**问题**: 当前只处理前缀NaN，中间的NaN仍会被拒绝
**方案**: 对中间NaN使用滚动统计插补（窗口5-10）
**收益**: 进一步提升因子通过率5-10%
**风险**: 可能引入偏差，需要验证

### 2. NaN来源追踪（优先级：低）

**问题**: 无法区分NaN来源（预热期/计算错误/数据缺失）
**方案**: 在FitnessResult中添加nan_source字段
**收益**: 便于调试和统计分析
**风险**: 增加代码复杂度

### 3. 动态阈值调整（优先级：低）

**问题**: 固定80%阈值可能过于严格
**方案**: 根据因子类型调整阈值（滚动窗口因子可放宽至90%）
**收益**: 更精细的控制
**风险**: 需要大量测试验证

### 4. 跨品种插补（优先级：极低）

**问题**: 单品种数据缺失时无法利用其他品种
**方案**: 实现PCA-based跨品种插补
**收益**: 理论上可提升数据利用率
**风险**: 实现复杂，不适合实时系统

## 总结

当前改进采用保守策略，在保持质量控制的前提下，通过LOCF填充处理滚动窗口预热期NaN，预期提升因子通过率15-20%。与前沿研究相比，未采用复杂插补方法，原因是期货数据质量高且实时性要求高。当前改进已足够应对期货因子的主要NaN问题，进一步改进需根据实际效果评估。
