# 因子表现完全相同问题根本原因修复

**时间**: 2026-05-30 23:45:00
**问题描述**: 不同因子的回测表现指标完全相同，理论上不同因子应该有差异。问题一直存在，修复多轮后仍复现。

---

## 问题调查过程

### 1. 数据库检查

查询数据库candidates表，发现：
- 20个因子记录中，18个不同的公式产生了**完全相同**的回测结果
- sharpe=3.500289, total_return=100.97061, total_trades=241等指标完全相同
- 说明问题不在前端显示，而在数据源头

### 2. 因子值计算测试

测试不同公式是否产生不同的因子值：
- `close - open`, `close - high`, `close - low` 产生了不同的因子值
- GPIndividual计算也正常，不同表达式产生不同因子值
- **结论**: 因子计算逻辑正常

### 3. 回测引擎测试

测试不同因子值是否产生不同的回测结果：
- 不同因子值产生了不同的回测结果
- sharpe、total_return、total_trades等指标有差异
- **结论**: 回测引擎逻辑正常

### 4. 日志分析

查看运行日志发现关键问题：
```
因子值统计: min=nan, max=nan, mean=nan, std=nan
回测结果: sharpe=1.3342, total_return=4.7974, total_trades=14
```

**关键发现**：
- 所有因子值都是NaN
- 但回测仍然产生结果
- 不同表达式产生相同回测结果

---

## 根本原因

### 原因1: 全NaN因子未被正确拒绝

**位置**: `backend/quant_engine/ops/gp_fitness.py`

**问题**:
- 之前添加的LOCF填充逻辑在全NaN情况下不会触发
- `first_valid_idx`为空时，没有返回错误
- 全NaN因子进入回测，产生无效但看似有效的结果

**影响**:
- 不同表达式产生全NaN因子
- 回测引擎对全NaN因子的处理不当
- 导致所有全NaN因子产生相同的无效回测结果

### 原因2: 参数类型检查失效

**位置**: `backend/quant_engine/ops/gp_fitness.py`

**问题**:
- 参数类型检查只在遗传算子中生效
- evaluate方法中没有验证参数类型
- 错误的参数类型（如`money_flow(high, 20, close, volume, 20)`）仍然通过评估

**影响**:
- 参数类型错误导致因子计算失败
- 产生全NaN因子
- 如`money_flow`的`low`参数被传入常量`20`，导致计算失败

---

## 修复方案

### 修复1: 全NaN因子检查

**文件**: `backend/quant_engine/ops/gp_fitness.py`

**修改内容**:
```python
# 在LOCF填充逻辑中添加全NaN检查
if nan_mask.any():
    first_valid_idx = np.where(~nan_mask)[0]
    if len(first_valid_idx) == 0:
        # 全NaN，直接拒绝
        logger.debug(f"个体 {individual.id} 因子值全为NaN，拒绝")
        return FitnessResult(
            individual_id=individual.id,
            expression=expression,
            valid=False,
            error_message="因子值全为NaN",
        )
```

**效果**:
- 全NaN因子被正确拒绝
- 不再产生无效的回测结果

### 修复2: 参数类型验证

**文件**: `backend/quant_engine/ops/gp_fitness.py`

**修改内容**:
```python
# 添加参数类型验证方法
def _validate_parameter_types(self, individual: GPIndividual) -> bool:
    """验证个体的参数类型是否正确"""
    from quant_engine.factors.registry import FACTOR_REGISTRY

    def validate_node(node: GPNode) -> bool:
        if node.node_type == 'func':
            func_meta = FACTOR_REGISTRY.get(node.name)
            if func_meta is None:
                return False

            for i, child in enumerate(node.children):
                if i >= len(func_meta.params):
                    return False

                param_name, param_type, param_default = func_meta.params[i]

                if param_type == str:
                    if child.node_type != 'var':
                        return False
                elif param_type in (int, float):
                    if child.node_type != 'const':
                        return False

                if not validate_node(child):
                    return False

        return True

    return validate_node(individual.root)

# 在evaluate方法中调用验证
if not self._validate_parameter_types(individual):
    logger.debug(f"个体 {individual.id} 参数类型验证失败")
    return FitnessResult(
        individual_id=individual.id,
        expression=expression,
        valid=False,
        error_message="参数类型错误",
    )
```

**效果**:
- 参数类型错误的因子被拒绝
- 避免因参数错误导致的全NaN因子

## 总结

**根本原因**:
1. 全NaN因子未被正确拒绝，导致无效回测结果
2. 参数类型检查失效，导致参数错误产生全NaN因子

**修复方案**:
1. 在LOCF填充逻辑中添加全NaN检测和拒绝
2. 在evaluate方法中添加参数类型验证

**预期效果**:
- 不同因子将产生不同的回测结果
- 数据库中因子表现将出现差异
- 因子质量提升，进化效率提高

这次修复解决了因子表现完全相同的根本原因，之前的多轮修复只解决了部分问题（数据列不匹配、回测引擎NaN检查），但遗漏了evaluate方法中的参数类型验证和全NaN检查。
