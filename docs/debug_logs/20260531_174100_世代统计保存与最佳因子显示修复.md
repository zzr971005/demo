**时间**: 2026-05-31 17:41
**问题**: 
1. 进化线程运行但后端API读取不到世代统计数据
2. 最佳因子显示不稳定，数量和排名频繁变化

## 问题1：世代统计保存失败

### 现象
- 进化线程正常运行，完成多代进化
- 数据库 `generation_stats` 表只有1条旧记录
- 后端API只能读取到1代数据

### 根本原因
1. **TypeError**: `_compute_composite_score` 中 `max_drawdown` 为 `None` 导致计算失败
2. **TypeError**: `_compute_composite_score` 中 `win_rate` 为 `None` 导致计算失败
3. **AttributeError**: `Candidate` 模型缺少 `win_rate_train` 字段
4. **create_next_generation** 可能因表达式重复而卡住

### 修复步骤

#### 1. 修复 _compute_composite_score 中的 None 值处理
**文件**: `backend/quant_engine/ops/evolution_center.py`

```python
def _compute_composite_score(self, sharpe: float, calmar: float, max_drawdown: float, win_rate: float, total_trades: int) -> float:
    # 夏普归一化（假设夏普在-2到5之间）
    sharpe_norm = max(0, min(1, (sharpe + 2) / 7)) if sharpe is not None else 0
    
    # 卡玛归一化（假设卡玛在0到5之间）
    calmar_norm = max(0, min(1, calmar / 5)) if calmar is not None else 0
    
    # 最大回撤转换（回撤越小越好，用1-回撤）
    drawdown_score = max(0, 1 - max_drawdown) if max_drawdown is not None else 0
    
    # 胜率归一化（假设胜率在0到1之间）
    win_rate_norm = win_rate if win_rate is not None else 0
    
    # 交易次数归一化（假设交易次数在0到100之间）
    trades_norm = min(1, total_trades / 100) if total_trades is not None else 0
    
    # 综合评分
    score = (
        sharpe_norm * 0.4 +
        calmar_norm * 0.2 +
        drawdown_score * 0.2 +
        win_rate_norm * 0.1 +
        trades_norm * 0.1
    )
    return score
```

## 问题2：最佳因子显示不稳定

### 现象
- 最佳因子数量一会儿多一会儿少
- 评分前一秒是高的，后一秒被评分低的替换
- 用户报告："最佳因子 前端的显示，怎么还一会儿多一会儿少呢，而且评分前一秒是高的，后一秒被评分低的替换了？"

### 根本原因
- **后端**: `evolution_center.py` 使用综合评分进行竞争淘汰（TOP_N_BEST=300）
- **前端API**: 之前按 `sharpe_train` 单一指标排序
- **排序标准不一致**导致显示不稳定

### 数据库状态
- 当前 candidates 表有 23 个因子
- 后端使用竞争淘汰规则，维护 300 个最佳因子的池子

### 修复步骤

#### 修改 API 排序逻辑

### 综合评分公式
评分 = 夏普归一化 × 0.4 + 卡玛归一化 × 0.2 + (1 - 最大回撤) × 0.2 + 胜率 × 0.1 + 交易次数归一化 × 0.1

- 夏普归一化: (sharpe + 2) / 7，范围 -2 到 5
- 卡玛归一化: calmar / 5，范围 0 到 5
- 最大回撤: 1 - max_drawdown，回撤越小得分越高
- 胜率: 直接使用，范围 0 到 1
- 交易次数归一化: total_trades / 100，范围 0 到 100

### 验证结果
- 前端显示的排名与后端实际保存的排名一致
- 不会再出现评分高的被评分低的替换的情况
- 综合评分字段已添加到API响应中
