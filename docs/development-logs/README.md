# 开发进展记录规则

## 目录结构

```
docs/development-logs/
├── README.md                 # 本文件 - 记录规则说明
├── YYYY-MM-DD-标题.md        # 每次开发进展记录文件
├── YYYY-MM-DD-标题.md        # 每次开发进展记录文件
└── ...
```

## 记录规则

### 1. 文件命名规范

- 格式：`YYYY-MM-DD-简短标题.md`
- 示例：`2026-05-17-交易执行模块完成.md`
- 必须包含日期和简要描述

### 2. 创建原则

- **禁止修改已有文件**：每次记录必须新建文件
- **禁止覆盖旧内容**：历史记录必须保留
- **按时间顺序排列**：文件名包含日期便于排序

### 3. 文件内容模板

```markdown
# 开发进展记录 - YYYY-MM-DD

## 本次开发内容

### 新增模块

#### 1. 模块名称

- **文件**: `文件路径`
- **功能**:
  - 功能点1
  - 功能点2
  - 功能点3

### API端点列表（如有）

| 端点 | 方法 | 说明 |
|------|------|------|
| /api/xxx | GET/POST | 说明 |

### 技术亮点

- 亮点1
- 亮点2

### 更新统计

```
新增代码文件:     X
新增后端代码:     X+
新增前端代码:     X+
API端点:         X个
核心类:          X个
```

## 关联信息

- 相关文件: `文件路径1`, `文件路径2`
- 依赖模块: 模块名称
- 测试脚本: `脚本路径`

## 备注

- 注意事项
- 后续优化方向
```

### 4. 记录时机

- 完成一个功能模块后
- 修复重要Bug后
- 重构代码后
- 添加重要功能后
- 每次开发会话结束时

### 5. 索引维护

每次创建新记录文件后，需要在 `INDEX.md` 中更新索引：

```markdown
# 开发进展索引

## 按时间排序

| 日期 | 标题 | 文件 | 主要内容 |
|------|------|------|----------|
| 2026-05-17 | 交易执行模块 | 2026-05-17-交易执行模块.md | TQSDK对接、交易网关、前端界面 |
```

## 违规后果

- 修改旧文件将导致历史记录丢失
- 覆盖内容将无法追溯开发过程
- 必须严格遵守"新建文件"原则
