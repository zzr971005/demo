## 2. 启动因子挖掘时的完整数据流

### 2.1 用户操作流程

```
用户点击"启动进化"按钮
        │
        ▼
前端调用 POST /api/evolution/start
{
  "symbols": ["RB"],
  "generations": 30,
  "population_size": 100,
  "max_stagnation": 0
}
        │
        ▼
后端创建 EvolutionTaskConfig 和 EvolutionCenter 实例
        │
        ▼
调度器创建任务并异步执行
        │
        ▼
进化循环开始：
  for generation in range(max_generations):
      1. 评估种群
      2. 选择精英
      3. 交叉变异
      4. 保存历史个体
      5. 发送WebSocket通知
```

### 2.2 进化过程中的数据产生

```
每个世代产生的数据：
┌─────────────────────────────────────────┐
│  GenerationStats (世代指标)             │
│  - generation: 1, 2, 3, ...             │
│  - avg_sharpe: 0.5, 0.6, 0.8, ...      │
│  - max_sharpe: 1.2, 1.5, 1.8, ...      │
│  - diversity_score: 0.3, 0.35, ...     │
│  - best_fitness: ...                   │
│  - avg_fitness: ...                    │
└─────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────┐
│  GPIndividual (遗传规划个体)             │
│  - id: "gen1_0001"                     │
│  - expression: "trend_strength(...)"   │
│  - fitness: { sharpe: 1.5, ... }       │
│  - metrics: { total_return: 10.5, ... }│
│  - generation: 1                       │
│  - origin: "elite"/"crossover"/"mutate" │
│  - parent_id: "gen0_0005" (可选)        │
└─────────────────────────────────────────┘
```

### 2.3 后端API产生的数据

| API 端点 | 数据内容 | 更新频率 |
|---------|---------|---------|
| `GET /api/evolution/status` | 进化状态、当前代数、进度 | 实时 |
| `GET /api/evolution/generations` | 所有世代的指标数据 | 每代更新 |
| `GET /api/factors/evolution` | 进化树节点(血缘关系) | 每代更新 |
| `GET /api/evolution/factors` | 进化出的因子列表 | 每代更新 |
| `GET /api/evolution/results` | 最佳因子详细指标 | 每代更新 |

## 5. 当前问题诊断

### 5.1 为什么页面没有反应？

可能的原因：

1. **API未调用或返回空数据**
   - 检查浏览器Network面板
   - 确认 `/api/factors/evolution?symbol=RB` 返回了数据

2. **前端未正确处理响应**
   - useEvolution hook 的数据转换逻辑
   - 状态更新是否触发重渲染

3. **后端数据未正确保存**
   - EvolutionCenter.historical_individuals 是否被填充
   - API端点是否从正确的来源读取数据

### 5.2 需要验证的API调用链

```
启动进化
    │
    ▼
POST /api/evolution/start
    │
    ▼
GET /api/evolution/status  ←── 应该返回 RUNNING + current_generation > 0
    │
    ▼
GET /api/evolution/generations?symbol=RB  ←── 应该返回世代指标数组
    │
    ▼
GET /api/factors/evolution?symbol=RB  ←── 应该返回树节点数组
    │
    ▼
GET /api/evolution/factors?symbol=RB  ←── 应该返回因子列表
```

## 6. 建议的修复方案

### 6.1 前端轮询机制

进化树页面应该添加自动刷新：

```typescript
// useEvolution.ts
useEffect(() => {
  if (!symbol) return

  // 立即加载一次
  fetchData()

  // 如果进化运行中，每5秒刷新一次
  const interval = setInterval(async () => {
    const status = await evolutionApi.getStatus()
    if (status.data.status === 'RUNNING') {
      fetchData()
    }
  }, 5000)

  return () => clearInterval(interval)
}, [symbol])
```

### 6.2 进化中心页面刷新

进化中心页面需要定期刷新状态和世代数据：

```typescript
// 类似的轮询逻辑
useEffect(() => {
  const loadData = async () => {
    const status = await evolutionApi.getStatus()
    setEvolutionStatus(status.data)

    if (status.data.current_symbol) {
      const gens = await evolutionApi.getGenerations(status.data.current_symbol)
      setGenerations(gens.data.generations)
    }
  }

  loadData()
  const interval = setInterval(loadData, 3000)
  return () => clearInterval(interval)
}, [])
```

### 6.3 WebSocket 实时更新

完善WebSocket推送，前端订阅更新：

```typescript
// 在各页面组件中
useEffect(() => {
  const unsub = wsClient.subscribe('factor_evolution', (data) => {
    if (data.symbol === currentSymbol) {
      // 触发数据刷新
      fetchData()
    }
  })
  return unsub
}, [currentSymbol])
```

## 7. 总结

当用户启动RB因子挖掘时，系统中的数据流动：

```
1. 用户点击 → API调用 → 后端创建任务 → 异步进化执行
                                                      │
2. 进化循环（每代）→ 评估 → 选择 → 交叉变异 → 保存个体
                                                      │
3. 数据可用 ← GET API 轮询 ←──────────────────────────┘
                    │
4. 前端状态更新 ← 响应处理 ←────────────────────────────┘
                    │
5. UI重渲染 ← 状态变化 ←──────────────────────────────┘
```

**当前问题：** 前端各页面没有实现自动刷新机制，导致即使后端数据在变化，前端也无法感知和更新显示。

**修复方向：** 在相关页面添加轮询机制或完善WebSocket实时推送，确保前端能够及时获取并展示进化过程中的数据变化。
