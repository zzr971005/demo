## 🔌 API连通性测试

### 📡 后端API连通性检查

**1. 检查后端启动**
```bash
# 端口监听检查
netstat -ano | findstr :8000

# 进程检查
tasklist | findstr python
```

**2. API健康检查**
```python
import requests

try:
    response = requests.get('http://localhost:8000/health')
    print(f"✅ API正常: {response.status_code}")
    print(f"响应内容: {response.json()}")
except Exception as e:
    print(f"❌ API连接失败: {e}")
```

**3. CORS配置验证**
```javascript
// 浏览器控制台执行
fetch('http://localhost:8000/api/dashboard/summary')
  .then(r => r.json())
  .then(d => console.log('✅ CORS正常', d))
  .catch(e => console.error('❌ CORS错误', e))
```

### 🌐 前端代理配置

**Vite代理配置检查** (`frontend/vite.config.ts`)
```typescript
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
      },
      '/ws': {
        target: 'ws://localhost:8000',
        ws: true,
      },
    },
  },
})
```

### 🔄 WebSocket连接测试

**浏览器控制台测试**
```javascript
const ws = new WebSocket('ws://localhost:5173/ws')

ws.onopen = () => {
  console.log('✅ WebSocket连接成功')
  ws.send(JSON.stringify({ type: 'ping' }))
}

ws.onmessage = (event) => {
  console.log('📩 收到消息:', JSON.parse(event.data))
}

ws.onerror = (error) => {
  console.error('❌ WebSocket错误:', error)
}

ws.onclose = () => {
  console.log('🔌 WebSocket连接关闭')
}
```

## 🧩 系统集成测试

### 📋 集成测试清单

#### 1. 端到端数据流测试
```
用户操作 → 前端API调用 → 后端处理 → 数据库操作 → WebSocket推送 → 前端更新
```

- [ ] 策略参数修改 → 后端接收 → 状态更新 → 前端实时显示
- [ ] 触发进化任务 → 任务队列 → 进度推送 → 前端更新
- [ ] 手动切换策略 → 对账确认 → 状态更新 → 通知推送
- [ ] 风险预警触发 → 告警生成 → 前端弹窗显示

#### 2. 跨模块集成测试

| 集成场景 | 涉及模块 | 测试步骤 | 预期结果 |
|---------|---------|---------|---------|
| 进化→验证 | 进化引擎+验证监控 | 1. 触发进化<br>2. 检查验证页面<br>3. 检查阶段状态更新 | 状态实时更新，数据一致 |
| 策略→风险 | 策略替换+风控 | 1. 替换策略<br>2. 检查风险报告<br>3. 检查告警 | 风险指标正确更新，告警正常 |
| 交易→持仓 | 交易执行+仓位对账 | 1. 模拟下单<br>2. 检查持仓<br>3. 执行对账 | 持仓数据一致，对账正确 |
| 调度→通知 | 调度器+WebSocket | 1. 设置定时任务<br>2. 等待触发<br>3. 检查通知推送 | 任务执行，通知实时推送 |

#### 3. 性能测试

**响应时间要求**
- API响应: < 200ms
- 页面加载: < 2s
- WebSocket推送延迟: < 500ms

**并发测试**
```bash
# 使用ab工具测试
ab -n 100 -c 10 http://localhost:8000/api/dashboard/summary
```

#### 4. 异常场景测试

- [ ] 数据库断开连接 → 系统降级 → 正常恢复
- [ ] Redis断开 → 缓存降级 → 重新连接
- [ ] API超时 → 前端重试 → 用户提示
- [ ] WebSocket断开 → 自动重连 → 状态同步
- [ ] 行情中断 → 策略暂停 → 恢复后重启

## 🐛 常见问题排查

### ❌ 后端启动失败

**问题1：端口被占用**
```batch
# 查看端口占用
netstat -ano | findstr :8000

# 清理端口
clean-ports.bat
```

**问题2：Poetry虚拟环境问题**
```batch
cd backend
poetry env list
poetry install
poetry shell
```

**问题3：数据库连接失败**
```batch
# 检查本地 PostgreSQL 服务状态
pg_isready -h localhost -p 5432

# 检查本地 Redis 服务状态
redis-cli ping
```

### ❌ 前端启动失败

**问题1：node_modules缺失**
```batch
cd frontend
npm install
```

**问题2：端口被占用**
```batch
# 检查5173端口
netstat -ano | findstr :5173
```

**问题3：TypeScript编译错误**
```batch
cd frontend
npm run type-check
```

### ❌ API调用失败

**问题1：CORS错误**
- 检查后端main.py的CORS配置
- 确认前端vite.config.ts代理配置

**问题2：404 Not Found**
- 检查API路径拼写
- 确认router已正确注册
- 查看FastAPI docs确认端点存在

**问题3：500 Internal Server Error**
- 查看后端控制台错误日志
- 检查数据库连接
- 验证请求参数

### ❌ WebSocket连接失败

**问题1：连接被拒绝**
- 后端WebSocket端点是否正确
- 代理配置是否包含/ws
- 检查防火墙设置

**问题2：连接频繁断开**
- 检查心跳机制
- 查看网络稳定性
- 检查服务器负载

## 📚 开发教学指南

### 🏗️ 开发环境搭建

**步骤1：安装依赖**
```batch
# 后端依赖
cd backend
poetry install

# 前端依赖
cd ../frontend
npm install
```

**步骤2：确认基础设施已启动**
```batch
# 确认本地 PostgreSQL 和 Redis 服务已运行
pg_isready -h localhost -p 5432
redis-cli ping
```

**步骤3：启动服务**
```batch
# 后端 (终端1)
cd backend
poetry run python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 前端 (终端2)
cd frontend
npm run dev
```

### 🎯 新功能开发流程

**后端API开发步骤**
1. 在 `backend/app/api/` 创建新的API文件
2. 定义Pydantic模型
3. 实现接口逻辑
4. 在 `app/api/routes/` 创建路由导出
5. 在 `main.py` 注册router
6. 启动服务测试

**前端页面开发步骤**
1. 在 `frontend/src/pages/` 创建页面组件
2. 在 `App.tsx` 添加路由
3. 在 `components/Layout.tsx` 添加导航
4. 在 `lib/api.ts` 添加API调用封装
5. 测试页面功能

**后端调试**
- 使用VS Code Python Debugger
- 在关键位置设置断点
- 查看console输出

**前端调试**
