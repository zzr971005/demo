# 期货因子验证流程说明

## 概述

期货因子验证系统采用四阶段流水线架构，确保只有高质量的因子进入实盘交易。每个阶段都有严格的筛选条件和淘汰机制。

## 四阶段流水线

### 1. Search（搜索阶段）

**目的**：生成大量候选因子表达式

**输入**：无（从零开始）
**输出**：唯一表达式集合

**逻辑**：
- 使用遗传算法（GP）生成因子表达式
- 每代生成 50 个个体
- 去重后保留唯一表达式
- 竞争模式：保持池中最多 100 个最佳因子

**数据来源**：
```python
# 从 evolution_tasks 表获取进化任务状态
# 从 candidates 表统计唯一表达式数量
search_output = len(unique_expressions)
```

**筛选条件**：
- 语义验证（C001-C303 检查）
- 表达式语法正确性
- 计算复杂度限制

---

### 2. Replay（回放验证阶段）

**目的**：对 Search 阶段的因子进行严格的风险指标筛选

**输入**：Search 阶段输出的唯一表达式数量
**输出**：通过风险筛选的因子数量

**逻辑**：
```python
# 获取该品种的所有候选因子
candidates = session.execute(
    select(Candidate).where(
        Candidate.symbol == task.symbol,
        Candidate.sharpe_train.isnot(None),
        Candidate.max_drawdown.isnot(None),
        Candidate.win_rate.isnot(None),
    )
).scalars().all()

# 应用筛选条件
filtered_candidates = [
    c for c in candidates
    if c.sharpe_train > 1.5          # 夏普比率 > 1.5
    and c.max_drawdown < 0.20        # 最大回撤 < 20%
    and c.win_rate > 0.55           # 胜率 > 55%
]
```

**筛选条件**：
1. **夏普比率 > 1.5**：风险调整后收益必须为正且足够高
2. **最大回撤 < 20%**：控制最大损失不超过本金的 20%
3. **胜率 > 55%**：确保交易成功率超过 55%

**数据来源**：
- `sharpe_train`：训练集夏普比率
- `max_drawdown`：最大回撤（小数形式，如 0.15 = 15%）
- `win_rate`：胜率（小数形式，如 0.60 = 60%）

**淘汰率**：通常很高（80-95%），这是正常现象

---

### 3. Validation（验证阶段）

**目的**：对 Replay 阶段的因子进行过拟合检验

**输入**：Replay 阶段通过的因子数量
**输出**：通过过拟合检验的因子数量

**逻辑**：
- 执行三项过拟合检验：
  1. **DSR（Deflated Sharpe Ratio）**：调整后的夏普比率
  2. **WFE（White's Reality Check）**：白氏现实检验
  3. **PBO（Probability of Backtest Overfitting）**：回测过拟合概率

**筛选条件**：
```python
# 三项检验必须全部通过
overall_passed = (
    dsr_passed and      # DSR 检验通过
    wfe_passed and      # WFE 检验通过  
    pbo_passed          # PBO 检验通过
)
```

**数据来源**：
- `passed_factors`：通过过拟合检验的因子数量
- 在 `evolution_tasks` 表中实时更新

**更新机制**：
- 每 100 代更新一次（持续进化模式）
- 进化完成后也会更新（仅当从未设置过时）

---

### 4. Demo（演示阶段）

**目的**：保持每个品种的前 20 名最佳因子，准备实盘交易

**输入**：Validation 阶段通过的因子数量
**输出**：前 20 名因子数量

**逻辑**：
```python
# 按夏普比率降序排序，取前 20 名
demo_candidates = session.execute(
    select(Candidate).where(
        Candidate.symbol == task.symbol,
        Candidate.sharpe_val.isnot(None),
        Candidate.max_drawdown.isnot(None),
        Candidate.win_rate.isnot(None),
    )
).scalars().all()

demo_candidates.sort(key=lambda x: x.sharpe_val or 0, reverse=True)
top_20 = demo_candidates[:20]
```

**筛选条件**：
- 按 `sharpe_val`（验证集夏普比率）降序排名
- 保持最多 20 个因子
- 后来者可以挑战并替换较弱的因子

**数据来源**：
- `sharpe_val`：验证集夏普比率（优先）
- 如果 `sharpe_val` 为空，使用 `sharpe_train`

**动态更新**：
- 新因子如果排名进入前 20，会替换掉排名靠后的因子
- 始终保持每个品种最多 20 个 Demo 因子

## 关键：数据流逻辑（2026-05-31 更新）

### 流水线约束原则
**核心原则：如果前一阶段没有输出，后一阶段也不可能有输出**

### 累计数据逻辑（重要）
**所有阶段的输入和输出都是累计值，反映从进化开始至今的总和**

```python
# 从 validation_pipeline_data 表读取所有代数据
all_pipeline_data = session.execute(
    select(ValidationPipelineData).where(
        ValidationPipelineData.symbol == symbol
    ).order_by(ValidationPipelineData.generation)
).scalars().all()

# 计算累计值（输入和输出都累计）
cum_search_input = sum(d.search_input for d in all_pipeline_data)
cum_search_output = sum(d.search_output for d in all_pipeline_data)
cum_replay_input = sum(d.replay_input for d in all_pipeline_data)
cum_replay_output = sum(d.replay_output for d in all_pipeline_data)
cum_validation_input = sum(d.validation_input for d in all_pipeline_data)
cum_validation_output = sum(d.validation_output for d in all_pipeline_data)
cum_demo_input = sum(d.demo_input for d in all_pipeline_data)
cum_demo_output = sum(d.demo_output for d in all_pipeline_data)

# 前端显示的累计值
search_input = cum_search_input  # 累计所有代的search_input
search_output = cum_search_output  # 累计所有代的search_output
replay_input = cum_replay_input  # 累计所有代的replay_input
replay_output = cum_replay_output  # 累计所有代的replay_output
validation_input = cum_validation_input  # 累计所有代的validation_input
validation_output = cum_validation_output  # 累计所有代的validation_output
demo_input = cum_demo_input  # 累计所有代的demo_input
demo_output = cum_demo_output  # 累计所有代的demo_output
```

## 数据流图

```
Search (生成表达式)
    ↓
Replay (风险指标筛选)
    ↓
Validation (过拟合检验) ← 依赖 Replay 输出
    ↓
Demo (前20名排名) ← 依赖 Validation 输出
    ↓
实盘交易
```

## 关键指标说明

### 夏普比率（Sharpe Ratio）
- 定义：年化收益率 / 年化波动率
- 意义：风险调整后收益
- 阈值：> 1.5（Replay阶段，2024-05-29 更新）

### 最大回撤（Max Drawdown）
- 定义：从最高点到最低点的最大损失
- 意义：控制最大风险
- 阈值：< 20%（Replay阶段）

### 胜率（Win Rate）
- 定义：盈利交易次数 / 总交易次数
- 意义：交易成功率
- 阈值：> 55%（Replay阶段）

### 过拟合检验
- **DSR**：考虑多重检验偏差的调整夏普
- **WFE**：检验策略是否显著优于基准
- **PBO**：检测回测结果是否过拟合

## 常见问题

### Q: Replay 通过率为什么这么低？
A: 这是正常现象。 Replay 阶段使用严格的风险指标筛选，大部分因子会因为回撤过大或胜率不足被淘汰。

### Q: Demo 阶段为什么只有 20 个因子？
A: 这是系统设计，保持每个品种最多 20 个最佳因子，便于管理和监控。

### Q: 为什么有些因子没有 sharpe_val？
A: sharpe_val 需要在验证集上计算，可能因为验证集数据不足或计算失败导致为空。系统会自动使用 sharpe_train 作为替代。

### Q: passed_factors 是什么？
A: passed_factors 表示通过过拟合检验的因子数量，是 Validation 阶段的核心指标。

## 性能优化

1. **并行计算**：各阶段可以并行处理不同品种
2. **缓存机制**：重复使用的指标会被缓存
3. **增量更新**：只计算新增因子的指标
4. **批量处理**：减少数据库查询次数

## 监控建议

1. **关注各阶段通过率**：异常低的通过率可能预示数据问题
2. **监控指标分布**：夏普、回撤、胜率的分布应该合理
3. **定期清理**：及时清理过期和低质量因子
4. **A/B 测试**：对比不同筛选条件的效果
